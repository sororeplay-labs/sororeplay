# Contributing

Start with an issue explaining the user problem, expected behavior, and how to reproduce it. Keep pull requests focused. Add tests that catch an actual defect or demonstrate a new behavior. Run npm ci, npm test, and npm run demo before sending a PR.

Use synthetic data and testnet. Do not commit private keys, JWTs, customer records, personal identity documents, or production credentials. Explain the source and scope of any captured fixture. Distinguish offline simulation from live network evidence.

Code is licensed under MIT. Keep source attribution and dependency licenses intact. Contributor tasks and acceptance criteria are in docs/ISSUES.md; they have not been published as GitHub issues.
